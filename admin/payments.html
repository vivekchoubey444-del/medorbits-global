Payment reconciliation

Practical checks for matching MedOrbits records with the payment provider.

✓
Verify provider references

Match the transaction ID and provider order or payment reference against trusted provider records.

₹
Check amounts and currency

Confirm amount in the smallest currency unit where applicable and verify that the currency is INR.

◷
Resolve pending transactions

Use verified provider status and signed webhooks. Do not treat a browser redirect as proof of payment.

↩
Match refunds independently

Verify refund reference, amount, settlement status and the original payment before closing reconciliation.

Financial data controls

Security and operational safeguards for payment administration.

⬡
Enforce role-based access

Require server-side permissions for transaction viewing, receipt access, exports and any refund operation.

▣
Protect receipts and exports

Serve files through authenticated endpoints and log access to financial records.

⚙
Keep payment state server-owned

Verify gateway signatures, webhook authenticity, idempotency and transaction state on the backend.

≡
Maintain an audit trail

Record privileged access, reconciliation changes and refund actions with actor, timestamp and reason.

Finance operations · By design

Secure transactions. Clear records.

Build a reliable payment workflow around verified provider callbacks, immutable transaction references, reconciled settlements, documented refunds and controlled receipt access. This interface is a payment register, not a payment gateway or a substitute for provider-side verification.

Financial security notice: This page is not an authorisation boundary. The backend must authenticate each request, enforce role-based permissions, validate all filters, rate-limit sensitive endpoints and audit access. Verify transaction states through trusted payment-provider APIs and authenticated webhooks. Never store or expose full card numbers, CVV, PINs, banking passwords, payment secrets or access tokens. Exported transaction files may contain personal information and must be handled according to your privacy, retention and accounting policies. Do not initiate or record a refund from this read-only page.
