Permission governance checklist

Use these practices when reviewing role assignments.

01
Apply least privilege

Grant the minimum permissions needed for a defined role. Remove unnecessary access when responsibilities change.

02
Separate sensitive duties

Limit privileged operations such as user administration, payment management, policy changes and security configuration.

03
Review changes regularly

Use an approval workflow for sensitive changes and record the actor, target, reason and outcome in the audit log.

⬡

Security controls

Permission management must remain protected beyond the user interface.

01
Server-side authorization

Check the authenticated user's permission for every protected API request. Never rely on hidden buttons or client state.

02
Protect privileged accounts

Require strong authentication and MFA where supported. Prevent self-escalation and preserve a safe recovery path.

03
Keep a complete audit trail

Record successful and rejected permission changes without exposing session tokens or credentials in logs.

Identity governance

The right access. Accountable decisions.

Keep permission policies documented, review high-impact privileges and maintain a traceable approval process. Use your backend's authorised policy workflow for changes to sensitive roles or permissions.
