Import workflow

Recommended checks before modifying production records.

01
Verify the source

Confirm file provenance, ownership, approval and the destination dataset before uploading.

02
Inspect and map columns

Check header names, field types, required values, duplicate identifiers and encoding issues.

03
Validate before committing

Use validation-only mode first. Review server-reported row errors and resolve rejected records.

04
Review the result

Confirm inserted, updated, skipped and rejected counts. Check the audit trail and recovery process.

✦

Data quality standards

Protect data integrity throughout the ingestion process.

A
Enforce schema validation

Validate data types, required fields, field lengths, enumerated values and dataset-specific rules on the server.

B
Prevent accidental overwrites

Use unique constraints, explicit update permissions, conflict detection and database transactions.

C
Keep the audit trail

Record the initiating administrator, source metadata, import mode, outcomes, timestamps and approval reference.

Integrity · Traceability · Trust

Reliable data begins before import. Every change should be traceable.

Keep datasets consistent with documented schemas, validated source information, controlled permissions and reviewable import outcomes. Use a validation-only run before applying changes to production data.

Security and data-integrity notice: This page is an administrative client interface, not an authorisation boundary. The backend must authenticate every request, enforce role-based and dataset-level permissions, validate uploaded files and mapped fields, limit file size and processing resources, protect against CSRF where applicable, and record import actions. Use transactions or documented recovery procedures for production updates. Do not upload passwords, secrets or unauthorised personal data. Client-side parsing does not replace server-side validation or malware scanning.
