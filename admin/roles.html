Permission principles

Design role definitions around real responsibilities and explicit boundaries.

◇
Least privilege

Grant only the permissions needed for a person's assigned duties.

♙
Separate responsibilities

Separate user administration, admissions review, content management and security oversight.

✓
Review assignments

Periodically check assigned users, remove obsolete roles and revoke access promptly.

⚙

Change control

Protect privileged role changes from accidental or unauthorised edits.

≡
Audit every mutation

Record who changed a role, which permissions changed and when the change occurred.

⬡
Protect privileged roles

Enforce immutable system-role rules and prevent accidental loss of the final administrator.

◷
Verify before rollout

Test role changes against backend permission checks before applying them in production.

Identity governance

Clear permissions. Confident administration.

Use server-side role definitions, centralised permission checks, audit trails and periodic access reviews. This interface is an administrative client; it does not independently secure APIs or establish a user's authority.
