Audit governance checklist

Recommended controls for trustworthy audit records.

01
Record meaningful events

Capture authentication outcomes, permission changes, privileged actions and material changes to important application records.

02
Protect record integrity

Restrict modification and deletion, separate audit privileges where practical and protect stored logs from application-level tampering.

03
Use reliable timestamps

Synchronise server clocks and store event timestamps consistently, preferably in UTC, for dependable incident investigation.

04
Apply retention and access policies

Define retention periods, review access regularly and avoid retaining unnecessary personal or authentication data.

!

Investigation workflow

Suggested steps when an event requires review.

A
Establish the event context

Verify the timestamp, actor, target resource, event category and outcome using trusted server records.

B
Correlate related activity

Compare relevant application, authentication, infrastructure and security records using appropriate correlation identifiers.

C
Escalate and document findings

Follow the incident response process, preserve relevant evidence and document remediation in the approved system of record.

Trust · Transparency · Governance

Visibility builds trust. Integrity makes it useful.

A useful audit trail is complete, appropriately detailed, access-controlled and protected from unauthorised alteration. Combine application logging with server-side monitoring, incident procedures and a documented retention policy.

Security and privacy notice: This page is an administrative client interface, not an authorisation boundary. The backend must authenticate every request, enforce role-based access, validate query parameters, apply appropriate CSRF protections where relevant and protect audit records against unauthorised changes. Never expose passwords, session tokens, API keys, authentication secrets or unnecessary personal data in audit responses. Record access to sensitive audit information where required by your security policy. A displayed event is only as trustworthy as the underlying logging, timestamp, retention and integrity controls.
