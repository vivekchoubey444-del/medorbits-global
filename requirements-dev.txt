# QUICK START
# =============================================================================
#
# 1. Create a virtual environment:
#
#    python -m venv .venv
#
# 2. Activate the environment:
#
#    Windows PowerShell:
#      .\.venv\Scripts\Activate.ps1
#
#    Windows Command Prompt:
#      .venv\Scripts\activate.bat
#
#    Linux / macOS:
#      source .venv/bin/activate
#
# 3. Upgrade pip:
#
#    python -m pip install --upgrade pip
#
# 4. Install development dependencies:
#
#    python -m pip install -r requirements-dev.txt
#
# =============================================================================
# TESTING, LINTING & FORMATTING
# =============================================================================
#
# Run automated tests:
#    python -m pytest
#
# Run tests with verbose output:
#    python -m pytest -v
#
# Run Python linting:
#    python -m ruff check .
#
# Check formatting without changing files:
#    python -m ruff format --check .
#
# Format Python files:
#    python -m ruff format .
#
# Apply supported automatic lint fixes:
#    python -m ruff check --fix .
#
# Run linting and formatting checks together:
#    python -m ruff check . && python -m ruff format --check .
#
# =============================================================================
# OPTIONAL COVERAGE WORKFLOW
# =============================================================================
#
# After enabling coverage and pytest-cov above:
#
# Run tests with coverage:
#    python -m pytest --cov --cov-report=term-missing
#
# Generate an HTML coverage report:
#    python -m pytest --cov --cov-report=html
#
# =============================================================================
# OPTIONAL SECURITY AUDIT

# After enabling pip-audit above:

# =============================================================================
# INSTALLATION & SECURITY POLICY
# =============================================================================
#
# 1. Install development packages inside an isolated virtual environment.
#
# 2. Review package releases, changelogs and security advisories before
#    upgrading dependencies.
#
# 3. Keep development-only dependencies separate from production packages.
#
# 4. Review transitive dependencies and vulnerability reports regularly.
#
# 5. Never store passwords, API keys, access tokens or private credentials
#    in this file.
#
# 6. A successful installation, lint check or test run does not prove that
#    the application is secure or production-ready.
#
# 7. Configure pytest, Ruff and coverage centrally in pyproject.toml when
#    appropriate for the existing project structure.
#
# 8. Add optional dependencies only when tests or engineering workflows
#    actually require them.
#
# 9. Use CI to validate the supported Python version and required checks.
#
# 10. Review lock-file changes before merging dependency updates.
#
# =============================================================================
# VERSION & COMPATIBILITY POLICY
# =============================================================================
#
# Target Python version: 3.10+
#
# Version ranges define accepted releases; they do not guarantee identical
# dependency resolution across machines or over time.

# For reproducible CI builds:
#   - Resolve and review exact dependency versions.
#   - Maintain a reviewed lock file or fully pinned requirements file.
